# 遮挡检修件取出：协作操作与保护邻近容器

这是尚未完成 GPU 物理验证的开发任务包，不能作为已验证的比赛提交。
`scores` 仍为 `NOT MEASURED`，`media` 仍为 `PENDING_UPLOAD`；它们不是分数或有效媒体 ID。
本文按任务设计方法论的六个部分记录改动、证据边界和后续工作。

## 1. 新颖性：公开结果，保留场景判断

公开指令要求把红色检修件放到绿色垫片并释放、恢复其他可移动设备、保护黄色容器，
同时说明本任务评测双臂协作和禁止工具/临时支撑。指令不再点名哪个物体挡路，
也不指定先移谁、哪只手抓谁或固定的左右分工。`run_task.py` 从 `task.json` 读取同一条指令；
策略可见的 `task.py` 模块说明也只提供目标、中性物体清单和公共操作区域。
这解决了旧指令把遮挡物身份、处理顺序和机械臂分工直接泄漏给模型的问题。

暂存操作区中心 `(0.20, 0.23, T+0.14)` 和至少 1 秒稳定要求仍作为公共约束提供，
不把评分所需的区域隐藏起来让策略猜数字。完整初态与评分规范供复现/审核使用；
不向视觉策略额外提供对象真值、评分历史、接触传感器或特权脚本的动作序列。

设计借鉴 ThinkGrasp [1] §3.2–3.3 的目标相关中间对象选择和动作后重新观察，
以及 BEHAVIOR 的对象/初态/目标分离、RoboCasa 的对象采样与终态合取。
本包不运行 ThinkGrasp 的感知/抓取系统。现有固定初态和特权开环 `demo()` 只能用来预检执行，
**尚不能证明新颖性、闭环推理增益或对场景变化的适应性**。
下一步需保持指令不变，增加改变遮挡依赖的配对场景，比较“总先移同一物体”、
“直接取目标”和每步重新观察的策略，并保存观察 ID、对象选择与中间画面。
这些场景变体目前尚未实现，不能把本包描述为已经具备场景族。

## 2. 构造效度：实际臂归属与过程证据

评分采用 Isaac Lab `ContactSensorCfg` 的逐指端、逐对象过滤机制，
并借鉴 bounded-embodiment-bench 逐臂检查、最终条件合取和单臂对照策略。
不沿用“末端靠近物体就算持有”的近似作为充分条件。

- 为左右臂的 `tip_left`、`tip_right` 各自建立传感器；每个传感器仅过滤一个目标刚体，
  分别监测盖板和检修件，共 8 个过滤视图。源链接由机器人资产解析，partner 来自实际场景配置。
- 机器人开启 `spawn.activate_contact_sensors=True`；传感器 `update_period=0.0`、
  `history_length=14`。适配器在每次 physics `scene.update` 后读取
  `normal_force_matrix_w`，强制检查单环境/单源/单 partner 的 `(1,1,1,3)` 形状，
  输出 `contact_mapping` 供 F0 核对。两个指端分别取力向量模长，不能相加后互相抵消。
- 每个 20 Hz 评分帧必须有全新的 12 个 240 Hz 子步，每个实际臂/对象均含两指数据。
  缺失、复用、负值、NaN、形状不符或采样间隔异常均不得授予成功。
  适配器异常应在验证报告中记为 `INVALID`，不能冒充策略已完成的有效失败回合。
- 持有要求两指持续接触（当前开发估计：开启 0.5 N、保持 0.2 N、持续至少 0.10 s），
  同时实际夹爪开度 ≤0.85、TCP 距对象中心 ≤3 cm。开度和距离自身不证明抓住。
- 暂持角色由实际接触确定；取件角色必须是另一只实际机械臂，允许左右交换。
  同一只臂顺次做完全部操作、另一臂仅靠近或轻碰，不能取得高分/满分。
- 检修件移动超过原有 1 cm 门槛之前，盖板必须完成原有连续 1 秒暂持。
  取件时需由另一臂持续抓持；只有两臂共同操作时检修件下表面达到 `T+0.085`，
  才记录有效抽取事件。直接把检修件摆到终点不能补出这个事件。
- 盖板必须保持控制至放置验证完成；检修件只能在目标几何区域内开始释放，允许释放后逐渐静止，
  之后不得离开该区域。目标放置和盖板归位均要求对应臂松爪退开，且两臂都无该物体的检测接触。
  安全违规永久锁存，最后恢复正确位置不能消除历史违规。

**证据边界：**法向接触、持续时间和 TCP 约束是交互归属证据，尚不是力闭合、真实承重或因果贡献证明。
盖板仍是可自由移走的刚体；“暂存区下方没有支撑”不代表它不能先放在别处。
当前区域和时序门槛是开发协议，尚未证明其来自必要的物理依赖。
若强单臂策略能安全完成公开目标，应修改场景（例如经验证的自复位部件）或任务定位，
不能仅用评分门槛宣称任何单臂解法都不可能。F4/F5 及撤掉支撑臂的配对实验必须核验这一点。

### 评分档位与状态更新

使用试验结束时的分数，`SCORE_OVER="end"`；下表取最高满足档位，不相加。

| 得分 | 条件（均要求无历史违规和完整遥测） |
| --- | --- |
| 0.00 | 违规、过程/证据缺失，或当前没有满足的档位 |
| 0.25 | 已完成连续 1 秒暂持，当前仍有归属明确的盖板持有 |
| 0.50 | 已记录不同臂协作抽取，当前盖板仍被控制、检修件仍被取件臂持有且下表面 ≥T+0.085 |
| 0.75 | 已完成连续 1 秒放置验证，当前目标位置、释放与无接触条件仍成立 |
| 1.00 | 已验证交付，目标保持合格，盖板归位且释放，整组终态再连续保持 1 秒 |

`score()` 最高返回 0.75；框架 `task_score` 仅在 `SUCCESS_HOLD_S=1.0` 完成后给 1.0。
`success()` 每个控制步消费一批接触、推进一次历史；`score()`、`distance()` 和 `diagnostics()` 只读。
接触去抖按物理子步积分，对象位姿、安全、阶段事件仍在 20 Hz 检查；
**本实现不宣称具备所有位姿/安全事件的子步检测**。reset 清空角色、接触历史、阶段和失败锁存。

## 3. 待实证校准的阈值

以下物理判据全部是**估计值，尚无 GPU 实测校准值**。CPU 测试只验证逻辑分支与接口，
不会把数字变成已验证的物性或可行性结论。原有位移、倾斜、速度和稳定时间门槛均保留；
新增接触门槛也须校准。单位：m、s、N、m/s、rad/s、角度 °；采用 world 坐标。
位移参考 reset 后静置中心，不能逐帧重置参考点；倾角为对象局部 +z 与 world +z 的夹角，忽略 yaw。

| 判据 | 当前值/比较方向 | 当前状态及验证对象 |
| --- | --- | --- |
| 保护容器最大三维位移/倾斜 | ≤0.005 m / ≤10°，全程采样 | 估计；正常操作与轻推/倾倒后扶正负例 |
| 盖板/检修件全程倾斜 | ≤25° / ≤30° | 估计；正常取放与超限恢复负例 |
| 自由物体 AABB 工作区 | x∈[0.04,0.49]，y∈[-0.34,0.34]，z∈[T−0.01,T+0.30] | 设计边界，运行可达性/碰撞尚未验证 |
| 暂持水平/高度误差、最低下表面 | ≤0.025 / ≤0.02 / ≥T+0.10 | 估计；正常暂持和边界往返 |
| 暂持倾斜/线速度/角速度 | ≤10° / <0.02 / <0.5 | 估计；持续持有和抖动负例 |
| 开始取件的位移门槛 | >0.01（距静置起点） | 估计；静置漂移与真实抽取区分 |
| 有效抽取的下表面高度 | ≥T+0.085 | 几何设计候选，尚未验证是否覆盖必要通道 |
| 目标水平/中心高度/下表面误差 | ≤0.015 / ≤0.005（距 T+0.021）/ ≤0.005（距 T+0.001） | 几何容差估计；须核对整个形状的支撑与边界 |
| 目标倾斜/线速度/角速度 | ≤10° / <0.01 / <0.5 | 估计；稳定放置与暂时停顿后滑出 |
| 盖板归位水平/竖直误差 | ≤0.01 / ≤0.005 | 几何容差估计；核对两支撑实际支撑与 yaw |
| 盖板归位倾斜/线速度/角速度 | ≤5° / <0.01 / <0.5 | 估计；落稳与回弹负例 |
| 抓持实际夹爪开度/TCP 距离 | ≤0.85 / ≤0.03 | 估计；真实夹持与邻近无接触对照 |
| 释放实际夹爪开度/TCP 距离 | ≥0.90 / ≥0.06，且两臂均无检测接触 | 估计；张爪未退出、仍贴靠等负例 |
| 每指接触滞回 | F_on=0.5 N，F_off=0.2 N（等于门槛时仍接触） | 新增估计；无接触噪声、真实抓持、滑脱 |
| 双指连续接触最短时间 | ≥0.10 s（240 Hz 下至少 24 个物理样本） | 新增估计；轻碰、漏报与真实持续持有 |
| 暂持/交付/最终成功稳定窗口 | 分别 ≥1.0 s，各 20 个连续控制样本 | 原有估计；正常脚本与边界抖动/延后失稳 |
| 协作期间接触空隙 | 双指去抖持续时间中不容许缺口；重新累计 0.10 s | 保守开发规则，实际漏报容忍度未校准 |
| reset 布局检查 | 各自由物体中心距名义点 ≤0.01，倾斜 ≤5° | 原有估计；静置后偏移和重复 reset |
| 四元数非退化 | 范数 >1e−9，且所有位姿/速度/遥测有限 | 数值完整性门槛，CPU 分支检查；非物理校准项 |

20 Hz 控制、240 Hz 物理、12 子步/控制步、2,400 步/120 s 是固定配置与预算，
不是已测运行耗时或已证明足够的预算。物理时序、实际 dt 和完整采样仍待 GPU 核验。

### Brev / Isaac Sim 校准计划

从零开始执行方法论 §3 的 12 回合计划，另加 2 个专用边界抖动回合，**初始预算共 14 次独立 reset**：

| 阶段 | 次数 | 策略/检查 |
| --- | --- | --- |
| C0 | 1 | 无操作静置，再逐臂逐物体接触探针；核对 source/partner、法向力、dt、材质及静置漂移 |
| C1 | 3 | 正常双臂脚本：名义初态 1 次；预先声明的小位姿扰动 1 次；低摩擦或较重对象的声明边界组合 1 次 |
| C2 | 4 | L-only、R-only、跳过必要过程/提前释放、闲置臂短暂触碰，各 1 次；争取终局接近正确的强负例 |
| B0/B1 | 2 | 边界抖动：1 次跨越位移/倾角/速度及接触开启关闭边界；1 次在放置区和稳定窗口边界反复进出、短暂停稳后再滑动 |
| C3 | 0 | 对以上原始轨迹离线扫阈值及相邻值，检查正负分离和判定翻转 |
| C4 | 4 | 冻结后的标准合法复跑、未用于校准且改变遮挡依赖的合法变体、更强单臂旁路、跳步负例，各 1 次 |

小扰动/低摩擦/遮挡变体和攻击策略都需先显式实现、版本化；当前启动器固定 `object_jitter=0`，
不支持把未实现的变体当作现成命令运行。变体 reset 的参考布局检查也必须对应其实际初态，
不能用宽松 reset 容差暗中采样。物理参数改变后相关回合必须重跑。
B0/B1 每次只在声明的时间段改变某一类条件，保留未触发安全锁存前的原始曲线，避免多个失败互相掩盖。

建立 `validation/metrics_spec.md`，写清单位、坐标、统计窗口、采样频率和比较方向；
记录每回合保护对象最大位移/倾斜、终局几何裕量、每指每对象接触曲线、
协作区间/最长缺口、释放后速度、连续稳定时长、越界/穿透和逐臂约束。
标签须由人工核验，不能由候选评分器循环生成。
对“越小越好”的指标，只有合法极值 `p`、违规极值 `n` 及测量余量 `delta` 满足
`p+delta < n-delta` 才选择其间候选阈值；样本重叠时修测量、动作或场景，不放宽语义上的损伤限制。
接触开启/关闭阈值从 C0/C1/C2 分别核验，不能跨引擎照搬参考实现的数值。

生成 `thresholds.yaml`（value/unit/direction/metric_definition/measurement_margin/
source_episode_ids/legal_range/rejected_range/status）、`calibration.csv`、
`calibration_report.md` 和逐回合曲线。无数据的状态保持 `uncalibrated`、未知来源/范围保持 `null`。
现有代码是可跑 CPU 测试的开发评分器；正式提交/验收前必须完成校准冻结和加载状态检查，
不能把当前常量当作正式校准配置。C4 不用于选阈值；若失败，升级版本并另取独立确认回合。

## 5. 验证状态

**截至本次修改，尚未执行过 GPU 物理仿真，没有真实成功回合、已校准阈值或上传媒体。**
CPU 合成测试验证评分流程、真实 `ObjectState`/任务加载器、历史锁存、reset、释放、
接触证据缺失、双向单臂代劳、跳步和角色互换；另检查 YAM URDF 的 IK/限位和少量前臂碰撞检查点。
这些测试不会证明摩擦抓持、碰撞求解、物理承重或 120 s 满分可行性。
旧文档的运动学数字不作为新版本的实测性能结论。

### 最小必要验证步骤

在 Brev 的 Linux + NVIDIA RTX 环境，固定 Isaac Lab-Arena 0.3.1 / Isaac Lab 3.0 /
Isaac Sim 6.1 和 YAM 依赖版本，至少完成方法论 §5 的 **7 次独立 reset 物理回合**。
